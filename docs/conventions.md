# finsh 자원 판정 규약안

finsh는 자원을 주기적으로 검사해 판정 결과를 DB에 저장한다. `top`에는 정리 후보만 표시한다. 판정은 삭제 명령이 아니며, 실제 정리는 사람이 `kill`을 선택한 뒤 안전 절차를 거친다.

---

## 1. 판정 기준

| 판정 | 기준 | DB 저장 | top 표시 | 비고 |
| :--- | :--- | :---: | :---: | :--- |
| **`ORPHAN`** | 서버에 연결되지 않은 공인 IP 또는 서버에서 분리된 추가 블록 스토리지 | O | O | OS 기본 부팅 디스크 및 작업 중 자원 제외 |
| **`ZOMBIE`** | NSTOP으로 7일 이상 정지 상태로 관측된 서버 | O | O | DB 최초 관측 시각(`first_seen_stopped_at`) 기준 |
| **`IDLE`** | 최근 7일간 RUN 상태, CPU 측정값 평균 5% 미만인 서버 | O | O | 수집 데이터 충족률 80% 이상 조건 |
| **`WAITING`** | NSTOP으로 관측됐지만 첫 정지 관측부터 7일 미만인 서버 | O | X | top 상단 요약 카운트에만 합산 |
| **`UNKNOWN`** | API 오류, 작업 중 상태, 관측 공백 또는 CPU 데이터 부족 | O | X | top 상단 요약 카운트에만 합산 |
| **`OK`** | 현재 정리 후보 조건에 해당하지 않는 정상 자원 | O | X | 스캔 시 상태 동기화용 |

* **`OK` 상태의 의미**: "이번 검사에서 발견 사항 없음"이라는 뜻이며, 앞으로도 필요한 자원이라는 보증은 아니다.
* **제외 조건**: 연결·해제 작업 중인 자원(`ATTACHING` 등)과 서버의 기본 OS 디스크는 `ORPHAN`으로 판정하지 않는다.

---

## 2. 매 스캔 실행 규칙

1. **전수 스캔**: 자원의 종류·현재 상태·연결 관계를 확인하고 모든 자원의 DB 판정을 갱신한다.
2. **정지 관측 (`ZOMBIE` / `WAITING`)**: 서버의 `NSTOP`을 처음 확인하면 `first_seen_stopped_at`을 기록하고 `WAITING`으로 둔다. 기준 기간이 지나도 정지 상태면 `ZOMBIE`로 변경한다. (서버 생성 시각은 정지 시작 시각으로 사용하지 않음)
3. **재가동 관측**: 서버의 `RUN`을 확인하면 정지 관측 시각을 지운다. 실행 중인 서버에만 `IDLE`을 검사한다.
4. **상태 동기화**: 미할당 IP가 서버에 연결되는 등 후보 조건이 사라지면 `ORPHAN` → `OK`처럼 판정을 갱신한다. 이전 후보를 `top`에 남겨 두지 않는다.
5. **예외 처리**: 조회가 실패하거나 근거가 부족하면 `OK`로 추정하지 않고 `UNKNOWN`으로 기록한다.

---

## 3. 설정값 (Settings)

| 설정 항목 | 운영 환경 | 시연 환경 |
| :--- | :--- | :--- |
| **ZOMBIE 관측 기간** | 7일 | 10분 |
| **IDLE CPU 조회 기간** | 최근 7일 | 최근 10분 |
| **IDLE CPU 평균 기준** | 5% 미만 | 5% 미만 |
| **CPU 데이터 충족률** | 예상 측정값의 80% 이상 | 예상 측정값의 80% 이상 |
| **스캔 주기** | 30분 | 수동 실행 또는 짧은 주기 |

---

## 4. 삭제 안전장치

1. `top`의 `ORPHAN`, `ZOMBIE`, `IDLE`은 검토 후보이며 `kill` 실행 시 **IaC(Terraform) 관리 자원** 및 **`chattr +i` 보호 자원** 여부를 검사하여 삭제를 거부한다.
2. 삭제 승인 시 즉시 지우지 않고 **휴지통(유예 기간 3일)**으로 이동한다.
3. 휴지통 보관 중 자원이 다시 사용되면 삭제를 멈추고 `trash-restore`로 복원할 수 있다.
